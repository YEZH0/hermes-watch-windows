# 04 · 验证与续签

原则：**先离线证明签名产物对了，再让设备说话。**
否则一旦设备表现不对，你无法区分"没签好"还是"没装好"。

---

## 1. 三层验证

| 层级 | 验什么 | 需要设备吗 | 失败说明 |
| --- | --- | --- | --- |
| L1 产物 | 签名后的 IPA 里 entitlements 是否有 `application-groups` | ❌ | 签名/申请环节出错 |
| L2 设备 | 手表 App 的 `GroupContainers` 非空 | ✅ | 安装没生效或装的是旧包 |
| L3 体验 | 手表打开 App 不报错，表盘可切换 | ✅ | 权限对了但表盘数据未就绪 |

L1 通过而 L2 不过，几乎都是"装的是旧包"——重装，别急着改代码。

## 2. L1：离线校验

```powershell
python .\scripts\verify_appgroup.py <签名后的.ipa>
```

脚本做两件事：

- 从每个 `embedded.mobileprovision` 里切出 CMS 包裹的 XML plist，读 `Entitlements`
- 在 Mach-O 里扫描所有内嵌的 entitlements blob（`<?xml … </plist>`），读同一个键

本机实测输出：

```
[watch profile]  Payload/HermesCompanion.app/Watch/HermesEnabler2.app/embedded.mobileprovision
  Name = iOS Team Provisioning Profile: com.example.HermesEnabler.<TEAMID>.watchkitapp
  Expires = 2026-11-19 09:39:23
  application-identifier = <TEAMID>.com.example.HermesEnabler.<TEAMID>.watchkitapp
  com.apple.security.application-groups = ['group.com.example.HermesEnabler.<TEAMID>']
  -> OK

[iphone profile] ... -> OK
[iphone binary]  ... -> OK
[watch binary]   ... -> OK
```

**4/4 OK 才算过。** 其中 `[watch *]` 两项是这次修复的核心——修复前这里是 `MISSING`。

### 拿不到签名后的 IPA 怎么办

iLoader/isideload 会在 `%TEMP%\HermesEnabler.ipa_extracted\Payload` 保留解包结果
（当 `delete_app_after_install = false` 时）。校验脚本可以直接读目录，不必重新打包：

```powershell
python .\scripts\verify_appgroup.py "$env:TEMP\HermesEnabler.ipa_extracted"
```

## 3. L2：设备侧确认 Group 容器

装好之后，最直接的判据是手表 App 能不能读写共享容器。
两种看法：

**A. 看 App 行为**（最快）
手表上打开 HermesEnabler：
- 不再弹出 *An App Group ID may be missing* → 权限生效
- 能正常列出/启用表盘 → 容器可读写

**B. 看设备日志**（更硬）
在 iPhone 侧抓 `log stream`，过滤 watch 上的 `HermesEnabler` 进程，
关注 `containerURLForSecurityApplicationGroupIdentifier` 相关行是否返回非 nil 路径。

## 4. L3：装表盘

顺序很重要，别跳步：

1. **先备份**（Backup MG）—— 确认备份真的成功再往下
2. 打开 Hermès 开关
3. **Restart Carousel**（重启表盘轮播，让新表盘被加载）
4. 在手表上切换到爱马仕表盘，确认显示正常

第 1 步失败就不要继续：表盘写入失败时，没有备份就只能重装。

## 5. 7 天续签

免费个人团队的 Profile 有效期 **7 天**（本机：签发 11-12，到期 11-19 09:39）。
到期后 App 会直接闪退/无法启动，这是正常的签名过期，不是数据损坏。

```powershell
.\scripts\run-hermesfix.ps1
```

脚本会自动复用已存私钥与证书，**不会新建也不会吊销**。

### 续签的三条铁律

| 做 | 不做 |
| --- | --- |
| 到期后重跑脚本 | ❌ 在 iLoader 里"撤销证书" |
| 保持同一 Apple ID | ❌ 换账号（会消耗新的证书额度） |
| 保持 iPhone 解锁 + 信任 | ❌ 删除 App / 清除数据 / 重置配对 |

免费账号只有 **3 张证书额度**，撤销一次就少一张，且不返还。

### 什么时候需要重装 App，而不是只续签

- Profile 过期太久，iOS 已经把 App 判为不可用
- 换过 Apple ID
- 换过手机

这几种情况下重新跑一遍签名安装即可，数据是否保留取决于 App 的容器是否还在。

## 6. 失败速查

| 现象 | 先查 |
| --- | --- |
| L1 里 watch 项 MISSING | 补丁没编译进去（检查 `sideloader.rs` 是否还有 `continue`） |
| L1 全 OK，L2 仍报错 | 装的是旧包 → 重装 |
| 登录 `-80045` / `-45061` | anisette 来源不一致，见 [docs/03](03-踩坑记录.md) B1/B2 |
| 签名时报证书数量超限 | 3 张额度用完，必须先清理（这一步需要你确认） |
| 装到 97% 卡住 | 数据线/信任问题，拔插重试，别中断 |
