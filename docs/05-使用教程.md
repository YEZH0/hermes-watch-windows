# 使用教程：从下载到手表装好

> 这份教程面向**只想用、不想编**的人。
> 全程不装 Rust、不装 Visual Studio、不碰命令行、不需要 iLoader。
> 用 standalone 版的话，连 .NET 都不用装。
> 你需要的只有：一台 Windows、一根数据线、你自己的 Apple ID 密码。

如果你是要**从源码重建**或想搞懂原理，看 [00-从零开始.md](00-从零开始.md) 和 [01-原理.md](01-原理.md)。

---

## 0. 先花 60 秒确认你能不能做

三项硬条件，缺一项就不用往下看了：

| 条件 | 怎么查 |
| --- | --- |
| **64 位 Windows 10 / 11** | 设置 → 系统 → 关于 → 系统类型 |
| **iPhone + Apple Watch 已经配对** | 手表能收到 iPhone 的来电通知就算已配对 |
| **你记得自己的 Apple ID 密码** | 待会儿要登录，且要能收到 6 位验证码 |

还有**两件事软件替你做不了**，必须你亲手点：

1. **6 位两步验证码**——只推送到你的受信任设备，没有短信兜底也必须你本人
2. **手表上打开「开发者模式」**——在手表屏幕上点，点完要重启手表（第 3 步）

> 免费 Apple ID 就够，不用花钱。代价是**签出来的 App 只有 7 天有效期**（第 10 步讲续签）。

## 1. 下载两样东西

建一个干净目录，比如 `D:\Hermes`，放进去就行。

| # | 下什么 | 从哪下 | 说明 |
| --- | --- | --- | --- |
| 1 | **HermesFixGui** | 本仓库 [Releases](https://github.com/YEZH0/hermes-watch-windows/releases) | 见下方「下哪个版本」 |
| 2 | **.NET 9 桌面运行时** | `dotnet.microsoft.com/download/dotnet/9.0` → *Desktop Runtime* → **x64** | 约 55 MB。**下了 standalone 就不用装** |
| — | ~~HermesEnabler.ipa~~ | **不用下了** | 已经打进 HermesFixGui，启动时自动放好并填上，见下方说明 |

### 下哪个版本

| 文件 | 大小 | 需要第 2 项吗 |
| --- | --- | --- |
| **HermesFixGui-standalone.exe** | 69 MB | **不需要**，双击就跑 |
| HermesFixGui.exe | 28 MB | 需要，先装好 .NET 9 |

不确定就下 **standalone**。它自带运行时，不用装东西，也不要管理员权限。

两个都带同一个签名引擎，功能完全一样。

### 核对一下有没有下错

`.NET 9` 别下成 *ASP.NET Core Runtime* 或 *SDK*，要的是 **Desktop Runtime**。
（只下 standalone 的话这条可以跳过。）

IPA 下来后可以核对指纹（可选，但建议）：

```powershell
Get-FileHash .\HermesEnabler.ipa -Algorithm SHA256
```

应当等于：

```
53a14e7e431f9c4e1b39aca76852f1a1207d551d489fc0d3a72791e0ad9b01bb
```

exe 的指纹：

```
standalone : 9d8476916acb745057b7a9636693ea117bd77135b43724345984f9add0c5eb49
runtime-dep: c38671d12516e0d8aadeb76b36b90907abb7d8215d6c23d9c283952b2709ba36
```

仓库根目录的 `SHA256SUMS.txt` 里还有引擎和脚本的哈希。

**指纹对不上就别用**——这个工具要拿你的 Apple ID 密码去登录，来路不明的 exe 不能碰。

### 1.1 EXE 和 IPA 是两个东西，版本号不用对齐

| | 是什么 | 谁在维护 |
| --- | --- | --- |
| **HermesFixGui.exe** | 签名工具。它**不包含**爱马仕表盘，只负责把 IPA 重签一遍再装进你的设备 | 本仓库 |
| **HermesEnabler.ipa** | 真正装到手表上的应用，爱马仕表盘在它里面 | 上游 [pookjw/HermesEnabler](https://github.com/pookjw/HermesEnabler) |

所以：

- **两个版本号不需要一致。** 工具 v1.3 既能签 1.5.4，也能签以后的新版本
- **工具更新**通常只改界面和流程，不改"签出来的东西"
- **换 IPA 版本**等于换了要装的应用，和工具版本无关

### 1.2 仓库里带的是哪一版

- 本仓库 `ipa/HermesEnabler.ipa` 就是上游 **1.5.4** 原版，一个字节没改，自检认的就是它
- 这一份**已经打进 HermesFixGui**：启动时按内容哈希释放到
  `%LOCALAPPDATA%\HermesWatch\ipa\HermesEnabler-<哈希前 8 位>.ipa` 并自动填入，所以你**不需要自己去找 IPA**。
  同内容不会重复写盘；换了内嵌版本会新建文件，旧的不影响使用
- **真机完整跑通过的是 1.5.1**（签名 → 装进手表 → 手表端不再报 App Group 错误）
- 1.5.4 与 1.5.1 只差内容更新：bundle id、可执行名、fat 架构（arm64 + arm64_32）、
  Info.plist 结构都没变，签名路径完全一样；**但没有重新做真机验证**
- 上游以后还会发新版。自检里提示「上游已发布 X，仓库里附带的是 1.5.4」是**提醒不是阻止**——
  照样能签，只是那一版没在这里跑过

想稳就用仓库 `ipa/` 里那份。想尝鲜自己去上游下，出问题别怪工具。

## 3. 打开手表开发者模式（最容易卡住的一步）

这一步不做，前面全白干，而且**报错很含糊**，可能一直卡在最后一步。

### 3.1 iPhone 上

1. 设置 → 隐私与安全性 → 拉到底 → **开发者模式**
2. 打开开关 → 提示要重启 → **重启 iPhone**
3. 重启后会弹窗问「要打开开发者模式吗」→ 点「打开」→ 输锁屏密码

> 如果找不到「开发者模式」这一项：先用数据线把 iPhone 连一次电脑（第 4 步），
> 让系统识别到设备，这个菜单通常就会出现。

### 3.2 手表上

1. 手表上：设置 → 隐私与安全性 → **开发者模式**
2. 打开 → 重启手表（长按侧边按钮 + 数码表冠）

### 3.3 判据

- iPhone：开发者模式开关显示为**已打开**
- 手表：设置 → 隐私与安全性 → 开发者模式，**能看到这一项**就说明路径对了（开关打开后手表会重启）
- 打开软件后，"手表开发者模式"那块显示**「已开启」**

> 从 1.5.0 起，软件会真的去手表上读这个开关，不再只写一句「需人工」。三种结论分别怎么办，见 §5.1。

### 3.3.1 两道「信任」门（1.5.1 补上）

软件要碰手表，必须先过两道信任，缺一道都走不通：

| 门 | 弹在哪 | 什么时候要过 |
| --- | --- | --- |
| **iPhone 信任这台电脑** | iPhone 屏幕上：「要信任此电脑吗」 | 第一次插线、换电脑、换手机、或者以前点过「不信任」 |
| **手表信任这台电脑** | Apple Watch 屏幕上：「信任这台电脑」 | 第一次连手表、手表还原过、换电脑 |

- **手机这道**：软件会自己发起请求，你只要在 iPhone 上点「信任」并输入锁屏密码。
  也可以单独跑 `hermesfix.exe --pair-phone` 先把它过掉。
- **手表这道**：手表上弹出「信任」时点它。**成功了就记在本机，下次不再麻烦你**；
  记录删掉（或换电脑）才会重新问。
- 两道门的记录存在 `%LOCALAPPDATA%\HermesWatch\pairing\`，只有当前 Windows 用户能读，
  里面有私钥但不含密码、验证码、Token，也不进日志。删掉这个目录 = 让这台电脑「忘记」设备。

### 3.4 手表设置里找不到「开发者模式」

有些 watchOS 版本在没收到过「开发者请求」之前，这一项是**不显示**的。这时不用刷机、不用重置、不用重新配对：

1. 打开 `HermesFixGui.exe`，在「3 · 开始」卡片里点 **「显示开发者模式入口」**
2. 手表收到请求后，设置 → 隐私与安全性 → 里就会出现「开发者模式」
3. 在手表上打开它 → 输入手表密码 → 重启 → 重启后再确认一次
4. 回到软件点 **「重新检测」**，看到「已开启」再继续

> **「入口显示出来」和「已经开启」是两件事。** 前者只是让菜单出现，开关还得你自己拨。
> 软件弹窗里也是这么写的，别跳过那一步。

> 这条链路用的是手表自己的 `com.apple.amfi.lockdown` 服务，只发 `action 0`（请求显示入口）。
> 它不会替你 enable、不会重启手表、不改任何系统设置。

## 4. 连线

1. 用**能传数据的线**把 iPhone 连到电脑（很多附赠线只能充电，换一根试）
2. iPhone 弹出「**要信任此电脑吗**」→ 点「信任」→ 输锁屏密码
3. **手表放上充电器**（安装阶段要求手表在充电且靠近 iPhone）
4. 确认手表和 iPhone 连的是**同一个 Wi-Fi**
5. 让 iPhone 保持**解锁、停在主屏**，整个过程中不要锁屏

### 判据

Windows「此电脑」里能看到你的 iPhone；软件自检里的「iPhone 连接服务」显示**通过**。

> 这一步的原理：软件不直接连手表，而是让 iPhone 上的 `com.apple.companion_proxy`
> 把「手表 lockdown 端口」转发出来，再由 iPhone 经蓝牙/Wi-Fi 推给手表。
> 所以 **iPhone 必须连着、必须信任**，而且 **iPhone 到手表这一段必须通**——
> 手表离太远、没在充电、锁着，转发照样建得起来，但手表一句都不会回。

## 5. 打开软件，先看自检

双击 `HermesFixGui.exe`。

首次启动会做两件事：把内嵌的签名引擎释放到 `%LOCALAPPDATA%\HermesWatch\engine\`，然后跑一遍**环境自检**。

自检共 6 项：

| 项目 | 通过的样子 | 不通过怎么办 |
| --- | --- | --- |
| 运行环境 | 64 位 Windows | 换 64 位系统，没别的办法 |
| 签名引擎 | 显示 xx MB 与路径 | 杀毒软件误删了，加白名单后重开 |
| 签名文件 | 程序自带 · HermesEnabler 1.5.4 · 指纹匹配 | 显示「没找到能签的 .ipa」说明内嵌那份没释放出来，点「选择」手动指定；显示「与仓库里的 1.5.4 不一致」也能签，只是不保证 |
| iPhone 连接服务 | 通过 | 回第 4 步：换线、重新信任、解锁手机 |
| Anisette 服务 | 通过 | 公共实例偶尔抽风，等几分钟重开软件 |
| 手表开发者模式 | 已开启 | 显示「未开启」回第 3 步；显示「无法确认」看 §5.1 |

**「无法确认」不是失败**，是它诚实地告诉你这一项这次没问到——原因会写在同一行。

自检里出现「未通过」就别急着点开始，先按上表处理。

### 5.1 手表开发者模式：三种结论分别怎么办

「3 · 开始」卡片里有一块「手表开发者模式」。软件启动时会自动检测一次，
也可以随时点「重新检测」重来。检测走的是和安装完全相同的链路（USB iPhone → companion proxy → 手表 lockdown），
所以这里的结论和真正安装时看到的一致。

| 徽章 | 含义 | 怎么办 |
| --- | --- | --- |
| 已开启（绿） | 手表回复 `developer_mode = true` | 直接往下走 |
| 未开启（红） | 手表回复 `developer_mode = false` | 回第 3 步打开；列表里没这一项就点「显示开发者模式入口」 |
| 无法确认（黄） | 手表锁着 / 连不上 / 服务问不出来 | 先解锁手表、确认和 iPhone 连着，再点「重新检测」 |

**没确认「已开启」时，「开始签名并安装」会被拦住。** 这不是刁难：签名那十几分钟会白跑，
免费账号的 3 张证书额度也可能被白白消耗一次。

两个按钮的分工：

- **重新检测**：重新读一次真实状态。手表解锁、打开开发者模式、重启之后都点它。
- **显示开发者模式入口**：只在「找不到这一项」时用。它请求手表把设置里的菜单显示出来，
  **不开启任何东西**；成功后按弹窗提示在手表上操作，再点「重新检测」。

> 手表锁着和开发者模式没开是两件不同的事：前者让你去解锁，后者让你去翻设置。
> 软件把它们分开提示，不要混着处理。

## 6. 填账号（IPA 不用管）

1. **「1 · 签名文件」已经填好了** —— 程序自带 `HermesEnabler.ipa`，首次启动释放到
   `%LOCALAPPDATA%\HermesWatch\ipa\` 并自动填入，下面一行绿字写着「程序自带 · 已就绪」
2. 填 Apple ID（完整邮箱，别只填前面的名字）
3. 填密码

自己有一份别版本的 IPA 也想签，点「浏览」或直接拖进窗口就能覆盖；想换回自带的，
把输入框清空重开程序即可。

> 密码只通过子进程的环境变量传给引擎，**不写磁盘、不进日志**。
> 日志里出现的账号和验证码都是 `••••••` 掩码。
> 但引擎本身要拿它去 Apple 服务器换 token——这一点绕不过去，请只在本机运行。

## 7. 开始，然后等 6 位码

点「**开始签名并安装**」。

跑到登录阶段时，界面里会出一条 **两步验证** 输入框。同时会有一个 6 位码的弹窗出现在你**某台** Apple 设备上。把 6 位数字填进去，回车。

> 验证码只在内存里回传给引擎，用完即弃，不落盘。

### 7.1 验证码到底发到哪了

**不一定是插着数据线的这台 iPhone。** Apple 会推送到这个 Apple ID 的**任一受信任设备**：

- 另一台 iPhone、iPad、Mac、Apple Watch
- 甚至可能是已经卖掉但还没从账号里移除的旧设备

所以第一件事是：**在所有 Apple 设备上找一遍**，包括抽屉里那台旧 iPhone。

### 7.2 三个按钮到底做什么

界面上的按钮会往引擎里写一条指令，引擎转成 Apple 的请求。**点了不等于一定送到。**

| 按钮 | 实际动作 | 该在什么时候用 |
| --- | --- | --- |
| **再推送** | 让 Apple 重新往受信任设备推一次 | 等了 30 秒以上没动静，或推送弹窗被误关了 |
| **短信** | 请求 Apple 改走短信通道 | 受信任设备不在身边 / 收不到推送 |
| **中止** | 结束本次登录 | 确实拿不到码，想重来 |

几个必须知道的事实：

- **点了「短信」不代表短信一定来。** Apple 可能拒绝降级到短信，也可能只给一个"其他验证方式"的入口。遇到这种情况只能回去找受信任设备。
- **验证码有效期很短**（几分钟）。收到后立刻填，别先干别的。
- **连续失败会被限流。** 反复点「再推送」很容易触发，这时候越点越糟，等十几分钟再试。

### 7.3 为什么别人的账号能用，我的就收不到

不同 Apple ID 的两步验证配置完全不同，这不是工具能改的：

| 你的账号情况 | 表现 | 能不能继续 |
| --- | --- | --- |
| 有多个受信任设备 | 码推到其中一台，容易找不到 | 能，挨个找 |
| 只有一台设备，且不在身边 | 只能等它回到身边 | 能，但得等 |
| 绑定的手机号已停用 | 短信收不到，推送也没设备 | 不能，先去 appleid.apple.com 改号码 |
| 账号近期有异常登录 | Apple 要求额外验证（改密码、回答安全问题） | 不能，先在浏览器里把账号恢复正常 |
| 新注册 / 刚改过密码的账号 | 验证更严，可能直接拒绝第三方登录 | 换一个常用账号试 |

### 7.4 判断问题出在哪一层

按这个顺序排除，别一上来就怀疑工具：

1. **浏览器能登录吗？** 打开 `appleid.apple.com`，用同一个账号密码登一次。
   - 浏览器都登不上 → 账号或密码问题，和这个工具无关
   - 浏览器要验证码但你收不到 → 受信任设备/手机号的问题，先去 Apple 那边修
2. **浏览器能登、软件收不到码？** 看软件日志里登录那几行，是不是卡在发码之前就报错了（比如网络、anisette）。
3. **软件里能看到输入框，但设备毫无反应？** 这才是「推送没送到」，用「再推送」或「短信」。
4. **填了码报错？** 码过期了（重新点「再推送」）或输错了（`0` 和 `O`、`1` 和 `l`）。

> 工具的边界很清楚：它只是替你在命令行里走 Apple 的登录流程。**账号侧的验证策略、设备是否可信、短信能不能发，都在 Apple 手里**，工具绕不过去，也不该绕过。

### 7.5「改发短信到」里那几个号码是什么

登录时如果引擎从 Apple 那边拿到了受信任号码列表，2FA 输入框下面会多一行「**改发短信到**」，每个按钮是一个号码的尾号，比如 `***78`。

- 点哪个，就走哪个号码的短信通道，等于替你回答 Apple 的「发到哪个号」。
- 只显示尾号，**完整号码不显示、不记录、不导出**。要确认是不是你的号，看尾号。
- 只列出引擎真的报上来的号码。没这一行，说明引擎这次没拿到列表（或者账号本来就没绑号码），不是软件坏了——直接用上面的「短信」或「再推送」。
- 号码尾号也可能对应你已经停用的旧号。发出去收不到，就换一个再试，别连续点。

### 7.6 把日志交出去之前

底部有「**导出日志**」。它存的是**屏幕上那份**，不是引擎的原始输出：

| 会被替换掉 | 替换成 |
| --- | --- |
| 完整手机号 | `***` + 后两位（原有的尾号掩码保留） |
| Apple ID 邮箱 | 首字母 + `***@域名` |
| 设备 UDID | 头 4 位 + `…` + 尾 4 位 |
| 路径里的 Windows 用户名 | `<user>` |
| 6 位验证码、密码 | 本来就不写进日志，只回显「已提交」 |

保留的是排错真正要用的东西：四个阶段的标记、错误码、失败原因、进度百分比、扫到的设备型号。

> 这是**尽力而为的脱敏，不是保密承诺**。格式能认出来的才挡得住；遇到没见过的输出格式可能漏。发出去之前自己扫一眼，别默认它是干净的。软件不会把日志上传到任何地方，导出只落在你选的本地路径。

## 8. 看懂五个进度块

界面上方五个块对应引擎的五个阶段。卡住时看它停在哪：

| 阶段 | 在干什么 | 卡在这里通常意味着 |
| --- | --- | --- |
| **1 登录 Apple** | Apple ID 认证 + 取 anisette 数据 | 密码错、验证码没回来、网络不通 |
| **2 签名** | 建证书、注册 App ID、开通 App Group、生成 Profile、重签 IPA | 免费账号 3 张证书用完了；或账号被风控（`-80045` / `-45061`） |
| **3 iPhone 安装** | 把签好的 App 装到 iPhone | iPhone 锁着、没点「信任」、线不通数据 |
| **4 Watch 连接** | 经 iPhone 的 companion proxy 转发到手表 lockdown 端口，握手确认手表可用 | **手表锁着（最常见）**、手表上还有「信任」弹窗没点、手表睡着 / 离太远 |
| **5 Watch 安装** | 把 Watch App 真正推到手表 | 手表安装协调器被上一次安装占着（等 30 秒）、手表中途锁屏 |

> 手表这一步失败时，**千万不要从 Apple ID 密码重来**。签名产物已经缓存好了，
> 解锁手表之后点「继续安装到手表」就行，见 8.2。

想中途放弃就点「停止」——它会连引擎子进程一起结束，不会留下半死不活的进程。

### 8.1 失败卡片上的错误码

失败时界面底部会出现一张红卡片，标题说人话，副标题给出稳定的错误码。对不上号时看这张表：

| 错误码 | 真实原因 | 你该做什么 |
| --- | --- | --- |
| `WATCH_LOCKED` | 手表锁屏了，watchOS 拿 `PasswordProtected` 回了握手 | **让 iPhone 和 Apple Watch 都保持解锁状态**（手表戴在手上、贴近 iPhone），再重新检测 |
| `WATCH_PAIRING_PENDING` | 手表屏幕上还有一个「信任」弹窗没人点 | 看手表屏幕点「信任」 |
| `WATCH_PAIRING_DENIED` | 弹窗里点了「不信任」 | 到 iPhone 的 Watch App 里确认手表还在配对，再完整装一次 |
| `WATCH_UNREACHABLE` | companion proxy 或手表 lockdown 端口连不上 | 确认手表解锁、在 iPhone 附近；iPhone 解锁、插线；蓝牙和 Wi-Fi 都开 |
| `WATCH_TIMEOUT` | 手表长时间没回应 | 抬腕唤醒手表，等十秒再试 |
| `WATCH_INSTALL_BUSY` | watchOS 安装协调器被上一个进程占着（`IXErrorDomain Code=48`） | 等 30 秒再点重试；连续失败就重启手表 |
| `WATCH_NOT_REGISTERED` | 这块手表的 UDID 没写进描述文件 | 重新完整安装一次，会为当前配对的手表重新申请 Profile |
| `WATCH_NOT_PAIRED` | iPhone 上根本没有配对的手表 | 先在 iPhone 的 Watch App 里把手表配对上 |
| `WATCH_APP_MISSING` | 这个 IPA 里没有 `Watch/` 下的手表 App | 换本仓库自带的 `ipa/HermesEnabler.ipa` |
| `IPHONE_LOCKED` | iPhone 锁屏 | 解锁 iPhone，弹「信任此电脑」就点信任 |
| `IPHONE_UNREACHABLE` | 找不到 USB 连接的 iPhone | 换根能传数据的线，插紧，解锁并信任 |
| `APP_VERIFICATION_FAILED` | 设备无法验证 App 完整性 | 描述文件和设备对不上，重新完整安装一次 |
| `AUTH_FAILED` | Apple ID 登录失败 | 查邮箱、密码、验证码；连续失败等十分钟或换网络 |
| `CERT_LIMIT` | 免费账号证书满了 | 到 developer.apple.com 删掉不用的证书（本工具不会替你吊销） |
| `SIGNING_FAILED` | 签名阶段失败 | 导出日志看技术详情，多半是 bundle 结构或描述文件问题 |
| `RESUME_UNAVAILABLE` | 上次的签名产物过期、被改、或换了设备 | 重新完整安装一次 |
| `UNKNOWN` | 没有识别的错误 | 导出脱敏日志反馈，技术详情里有完整原始错误链 |

配对阶段的四个提示码（1.5.1 起）：

| 码 | 真实原因 | 你该做什么 |
| --- | --- | --- |
| `PHONE_TRUST_TIMEOUT` | 请求已经发到 iPhone，但 60 秒内没人点「信任」 | 解锁 iPhone，在「要信任此电脑吗」上点**信任**并输入锁屏密码 |
| `PHONE_LOCKED` | iPhone 锁着，配对请求被直接拒 | 解锁 iPhone 再重试 |
| `PHONE_TRUST_DENIED` | 在 iPhone 上点了「不信任」 | 拔线重插，这次点「信任」 |
| `WATCH_TRUST_TIMEOUT` | 请求已经发到手表，但手表没确认 | 解锁手表、戴在手上、屏幕亮着，看到「信任这台电脑」就点「信任」 |

**界面上不会把 Watch 阶段的问题说成「Apple ID 密码错」。** 提示什么，完全由错误码决定；
卡片上的动作是照着能做的写的（在哪、点什么），不是「请检查设备状态」这种空话。

### 8.2 手表那步失败了：不用重新登录，直接续装

签名一完成，产物（还没装的那份 `.app` 和各自的 `embedded.mobileprovision`）会存到本地缓存：

```
%LOCALAPPDATA%\HermesWatch\signed\<16 位缓存 id>\
    app\              ← 签好的 .app 目录
    manifest.json     ← 设备 UDID、bundle id、每个 profile 的到期时间、整棵树的哈希
```

缓存目录只授权给当前用户（`icacls /inheritance:r`），里面**没有**密码、验证码、Token、
配对文件或私钥。复用前会重新算一遍整棵树的哈希，并检查 profile 还没到期。

失败卡片上三个按钮的区别：

| 按钮 | 做什么 | 什么时候点 |
| --- | --- | --- |
| **我已处理，重新检查** | 跑一次只读探测（`--probe-watch`），确认手表现在解锁了、连得上 | 你刚解锁手表 / 点了信任之后 |
| **继续安装到手表** | 只重跑第 4、5 段，复用缓存里签好的产物 | 上一步显示「手表已解锁并连上」之后 |
| **查看技术详情** | 展开原始错误链和最近 24 行引擎输出 | 想搞清楚到底报了什么 |

顺序是强制的：**没通过「重新检查」，「继续安装到手表」是灰的**——不然就是在手表还锁着的时候
再撞一次同样的墙。检查没通过时卡片会保留原来的进度，绝不会显示成装完了。

只重跑手表时引擎会自己核对：现在连的 iPhone、现在配对的手表，是不是签名时那两台。
对不上就直接说 `RESUME_UNAVAILABLE`，不会拿别人的描述文件去装。

清空这份缓存（换账号、想腾空间）：

```powershell
.\hermesfix.exe --purge-cache
```

## 9. 怎么算成功

按顺序确认，四步全过才算真的成功：

1. iPhone 桌面上出现 **HermesEnabler** 图标
2. **手表上**也出现 HermesEnabler（在手表的应用列表里）
3. 手表上打开它，**不再报** *An App Group ID may be missing*
4. 手表 App → 表盘 → 能看到爱马仕表盘并可以选

> 界面上五个进度块全变绿、底栏显示「完成」，只代表**电脑端**的指令走完了。
> 手表上到底生效没有，还得照上面 4 条自己看一眼——第 3、4 条电脑替你看不了。

### 第 3 步报错了怎么办

那说明 App Group 没写进去。先跑一次离线校验（需要电脑上有 Python 3）：

```powershell
python .\scripts\verify_appgroup.py <签名后的.ipa>
```

签名后的 IPA 在软件日志里会打印路径。期望看到 4 项全 OK：

```
[watch profile]  ... com.apple.security.application-groups = ['group.com.example.HermesEnabler.<TEAMID>']  -> OK
[iphone profile] ... -> OK
[iphone binary]  ... -> OK
[watch binary]   ... -> OK
```

- **4 项全 OK，手表还报错** → 签名没问题，是手表端没刷新生效：把手表上的 HermesEnabler 删掉，重跑一次
- **watch 那两项 NOT OK** → 引擎版本不对（用到了没打补丁的 isideload），换本仓库的 exe

## 10. 7 天后会失效，怎么续

免费账号签出来的 Profile **只有 7 天**。到期后手表上的 App 会打不开，这是正常的，不是你弄坏了。

续签只要 2 分钟：

1. 把 iPhone 连上电脑、解锁、信任
2. 手表放充电器
3. 打开软件 → 选同一个 IPA → 填账号 → 开始

**要注意的：**

- ⚠️ **不要**在 iLoader 里点「撤销证书 / 删除 App / 清除数据」——免费账号一共只有 **3 张**证书额度，用光就只能等
- 同一张证书会**复用**，续签不会重复消耗额度
- 换电脑、换 Apple ID 都要重新来一遍

## 11. 出问题怎么查

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 双击 exe 没反应 / 提示缺运行时 | 没装 .NET 9 **Desktop** Runtime | 换 standalone 版最省事；或用第 2 步装 Desktop（不是 ASP.NET） |
| 一直停在「登录」 | 密码错 / 验证码没填 / 网络不通 | 重开软件再来一次 |
| 报 `-80045` / `-45061` | Apple 账号被风控，anisette 与 client-info 来源不一致 | 与本工具无关，换个网络或等一段时间再试 |
| 卡在「准备」，提示证书数量超限 | 免费账号 3 张证书用完了 | 等已有的过期（约 7 天），或在 iLoader 里清理，**但清理本身也算消耗** |
| 卡在「安装」 | 手表没开开发者模式 / 没在充电 / 没连上 | 回第 3、4 步 |
| 手表报 *App Group ID may be missing* | 引擎没用打补丁的版本 | 用本仓库的 exe，别用别处下的 |
| 自检「iPhone 连接服务」不通过 | 线只能充电 / 没信任 / 手机锁屏 | 换线、拔了重插点信任、解锁 |
| 自检「Anisette 服务」不通过 | 公共实例不稳定 | 等几分钟重开 |

更多底层原因见 [03-踩坑记录.md](03-踩坑记录.md)。

## 12. 能不能把我的成果发给别人

**不能发签好的 IPA。** 里面嵌了你的证书和 Provisioning Profile，绑死了你的 Team ID 和你的设备 UDID：
别人的手机不在你的设备列表里，装不上；就算装上，7 天后也一起过期。

能分享的是**工具 + 未签名的 IPA**，让每个人用**自己的** Apple ID 重签一次：

> 把这个仓库地址发给对方 → 对方照这份教程从第 1 步做一遍。
> 各自消耗各自的 3 张额度，互不影响。

## 附：不想用图形界面

仓库也带命令行版本，效果一样：

```powershell
# 把 HermesEnabler.ipa 放到仓库根目录，然后：
.\run-hermesfix.cmd

# 让 iPhone 现在就弹出「信任此电脑」并记住这台电脑（配对不成功时先跑这个）
.\hermesfix.exe --pair-phone

# 只检查手表通不通、锁没锁，不装任何东西
.\hermesfix.exe --probe-watch

# 只读检测手表开发者模式（0 已开启 / 4 未开启 / 5 无法确认），不装任何东西
.\hermesfix.exe --probe-dev-mode

# 请求手表把「开发者模式」设置入口显示出来（只显示，不开启、不重启）
.\hermesfix.exe --reveal-dev-mode

# 手表那步失败后：只重跑手表，复用上次签好的产物
.\hermesfix.exe --resume-watch

# 换账号 / 腾空间：删掉本地签名缓存
.\hermesfix.exe --purge-cache

# 不登录、不联网，只读解析 IPA 里有没有手表 App
.\hermesfix.exe --inspect .\HermesEnabler.ipa

# 校验（对签名后的 IPA）
python .\scripts\verify_appgroup.py .\HermesEnabler.ipa
```

退出码：`0` 成功，`2` 硬失败，`3` 手表阶段失败但可以只重试手表；
`--probe-dev-mode` 另有 `4` 未开启 / `5` 无法确认。

> 别直接右键运行 `.ps1`——Windows 默认执行策略会拦。
> `.cmd` 入口已经带了 `-ExecutionPolicy Bypass`，不改你的系统设置。
