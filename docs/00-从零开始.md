# 00 · 从零开始：照着做就能装完

> 这份是**唯一需要按顺序读的文档**。每一步都有「判据」——达不到就不要往下走，
> 否则后面每一步都会连带失败，而且很难判断问题出在哪一层。
>
> 全流程 **Windows x64 + 免费 Apple ID**，不需要 Mac、不需要付费开发者账号、不需要越狱。

## 开始之前，先确认你没有这三样东西

| 不要做的事 | 为什么 |
| --- | --- |
| ❌ 重置手表配对 / 抹掉设备 | 手表侧重新配对要几十分钟，且不解决任何问题 |
| ❌ 在 iLoader 里点「撤销证书 / Revoke」 | 免费账号只有 **3 张证书额度**，撤销不返还 |
| ❌ 升级 iOS / watchOS | 新版本可能让整条链路失效，先把当前的跑通 |

## 全流程一览

```
阶段 0  准备电脑            ── 10 分钟，纯电脑操作
阶段 1  打开手表开发者模式   ── 20 分钟，需要动设备
阶段 2  iLoader 登录并装一次 ── 15 分钟，需要 2FA
阶段 3  hermesfix 重签      ── 5 分钟
阶段 4  验证权限            ── 1 分钟
阶段 5  装表盘              ── 5 分钟
阶段 6  7 天后续签          ── 2 分钟
```

**只有阶段 1 和阶段 2 有可能卡住。** 阶段 3 之后基本是一次过的。

---

# 阶段 0 · 准备电脑

## 0.1 确认系统

Windows 10 / 11，x64。打开 PowerShell：

```powershell
[Environment]::Is64BitOperatingSystem
```

**判据**：输出 `True`。

## 0.2 安装 Apple 的设备驱动

必须让 Windows 能通过 USB 跟 iPhone 通信。装下面**任意一个**：

- Microsoft Store 搜 **Apple Devices**（推荐，体积小）
- 或 iTunes（苹果官网版，不要装 Microsoft Store 版的精简 iTunes）

装完确认服务在跑：

```powershell
Get-Service "Apple Mobile Device Service" | Select-Object Status, Name
```

**判据**：`Status` 为 `Running`。

> 如果服务不存在，说明设备驱动没装好。**不要继续**，先把这一步解决。

## 0.3 安装 Git 与 Python

```powershell
git --version
python --version
```

**判据**：两条都有版本号输出。Python 要 **3.9 以上**（3.11 / 3.12 最稳）。

缺 Git：https://git-scm.com/download/win
缺 Python：https://www.python.org/downloads/windows/ （安装时勾选 *Add python.exe to PATH*）

## 0.4 连接 iPhone 并信任

1. 数据线连接 iPhone 和电脑
2. iPhone 上弹出「要信任此电脑吗」→ **信任** → 输入锁屏密码

```powershell
# 确认 Windows 能看到设备（需要 iTunes/Apple Devices 已装）
Get-PnpDevice -Class USB | Where-Object { $_.FriendlyName -like "*Apple*" } | Select-Object Status, FriendlyName
```

**判据**：列出至少一条 `Apple Mobile Device (USB)` 且 `Status` 为 `OK`。

> **阶段 0 完成标志**：驱动在跑、Git/Python 可用、iPhone 已信任。
> 这三条任一不满足，后面所有步骤都会以各种奇怪的方式失败。

# 阶段 1 · 打开手表开发者模式

**原理**：Apple Watch 没有 USB 口，所有命令必须经 iPhone 的 `CompanionProxyService` 代理下发。
xtool 的 `feat/experimental-watchos` 分支提供了现成脚本。

## 1.1 把设备摆好（这步不做，后面 100% 失败）

- [ ] 手表**放在充电器上**（不充电时手表会断连）
- [ ] 手表与 iPhone 在**同一个 Wi-Fi**
- [ ] 手表已解锁并保持亮屏
- [ ] iPhone 已解锁、已 USB 连接电脑
- [ ] 手表和 iPhone 的蓝牙/Wi-Fi 都开着

## 1.2 获取 xtool

```powershell
cd $HOME
git clone --depth 1 --branch feat/experimental-watchos https://github.com/oacevedo/xtool.git
cd xtool
```

**判据**：目录下存在 `tools\watchos\watch_device.py`。

```powershell
Test-Path .\tools\watchos\watch_device.py
```

## 1.3 建虚拟环境并装依赖

```powershell
py -3.11 -m venv .watchos\venv
.\.watchos\venv\Scripts\python.exe -m pip install --upgrade pip -q
.\.watchos\venv\Scripts\python.exe -m pip install -r .\tools\watchos\requirements.txt
```

> Python 版本无所谓，3.11 / 3.12 / 3.13 都能跑。`py -3.11` 换成 `py -3.12` 也行，
> 但要和后面所有命令里的路径保持一致。

**判据**：安装过程无红色报错，且能打印版本：

```powershell
.\.watchos\venv\Scripts\python.exe -c "import pymobiledevice3; print(pymobiledevice3.__version__)"
```

期望输出 `11.31.0` 或同系列版本。

## 1.4 建立与手表的配对记录

```powershell
.\.watchos\venv\Scripts\python.exe .\tools\watchos\watch_device.py --pair --device-info .watchos\device.json
```

**判据**：生成 `.watchos\device.json`，里面记着手表的 UDID。

```powershell
Get-Content .watchos\device.json
```

> 脚本内部有 120 秒超时。超时基本都是因为手表不在充电器上、或不在同一 Wi-Fi。

## 1.5 让「开发者模式」开关出现在手表上

```powershell
.\.watchos\venv\Scripts\python.exe .\tools\watchos\watch_device.py --reveal-developer-mode
```

**判据**：命令成功返回，且手表 **设置 → 隐私与安全性** 里出现「开发者模式」条目。

## 1.6 在手表上手动开启（必须人工操作）

1. 手表 → **设置 → 隐私与安全性 → 开发者模式**
2. 打开开关
3. 手表提示**重启** → 确认重启
4. 重启后再次确认开关是开的

## 1.7 验证（不要跳过）

```powershell
.\.watchos\venv\Scripts\python.exe .\tools\watchos\watch_device.py
```

**判据**：输出中出现

```
developer_mode: True
```

看到 `True` 才算过。**不要凭"设置里看到开关"判断**——开关是开的但设备没真正进入开发者模式，后面签名会失败。

> **阶段 1 完成标志**：`developer_mode: True`。

> **阶段 1 仍然可以独立使用，1.5.0 没有替换它。**
> `HermesFixGui.exe` 里后来加了同样两件事——读 `developer_mode`、请求显示设置入口——用的是同一条链路
> （USB iPhone → companion proxy → 手表 `com.apple.amfi.lockdown`），只是把上面的命令包成了按钮：
> 自检里的「手表开发者模式」等价于这里的 `developer_mode` 取值，「显示开发者模式入口」等价于
> `--reveal-developer-mode`。两条路结果一致，走通一条就够：
>
> - 没装 Python、不想碰命令行 → 用软件里的按钮（见 [docs/05 §3.4](05-使用教程.md)、§5.1）
> - 已经在终端里跑到 `True` → 软件里的检测也会显示「已开启」，直接往下走

# 阶段 2 · iLoader 登录并先装一次

**为什么必须先做这一步**：后面的 `hermesfix` 不会新建证书，它**复用 iLoader 写进 Windows 凭据管理器的私钥、证书和 anisette 状态**。
没有这一步，`hermesfix` 无从下手。

## 2.1 下载 iLoader

到 https://github.com/AndreySemjonov/iloader/releases 下载 **`v2.3.4-fork.2`** 的 Windows 产物。

```powershell
# 下载后校验（可选但推荐）
Get-FileHash .\<下载的文件>.exe -Algorithm SHA256
```

同目录的 `SHA256SUMS.txt` 里有官方哈希，对得上再用。

## 2.2 登录 Apple ID

打开 iLoader → 登录入口 → 输入 Apple ID 和密码。

**两步验证注意**：Apple **默认不发短信**，而是把 6 位码推送到受信任设备的弹窗里。

- iPhone 会弹「Apple ID 登录」→ 点 **允许** → 码显示在屏幕上
- 收不到时再考虑短信

**判据**：iLoader 里显示已登录，且能看到你的开发团队（免费账号显示为个人团队）。

## 2.3 用 iLoader 装一次 HermesEnabler

1. 拿 IPA：**直接用本仓库 `ipa/HermesEnabler.ipa`**（1.5.4，上游原版没改过）
   ；要自己去上游下也行：https://github.com/pookjw/HermesEnabler/releases/download/1.5.4/HermesEnabler.ipa
2. 在 iLoader 里选择这个 IPA
3. 目标设备选你的 iPhone
4. 开始安装，保持 iPhone 解锁、连接

**判据**：日志走到 `InstallComplete`，iPhone 和手表上都出现 HermesEnabler 图标。

> 装好后去手表上打开 HermesEnabler，**大概率会报 `An App Group ID may be missing`**。
> **这是预期的**——正是阶段 3 要修的东西。看到这个报错说明阶段 2 成功了。

> 装完 iPhone 可能从设备列表消失（usbmux 会话被回收）。拔插数据线即可，**不用重新配对**。

> **阶段 2 完成标志**：iLoader 里能正常登录、HermesEnabler 已在两端装上、手表报 App Group 错误。

# 阶段 3 · 用 hermesfix 重签（核心）

## 3.1 获取本仓库

```powershell
cd $HOME
git clone https://github.com/YEZH0/hermes-watch-windows.git
cd hermes-watch-windows
```

如果仓库还没公开，用你手上的压缩包解压到任意**纯英文路径**（例如 `C:\hermes`）。
**不要放在含中文的路径下**，PowerShell 脚本和部分工具会出问题。

## 3.2 放入 IPA

把 `HermesEnabler.ipa` 复制到仓库根目录：

```
hermes-watch-windows\
├─ HermesEnabler.ipa      ← 放这里
├─ run-hermesfix.cmd
└─ ...
```

**判据**：

```powershell
Test-Path .\HermesEnabler.ipa
```

## 3.3 检查前置条件（30 秒，能省半小时）

- [ ] iPhone 已 USB 连接、已解锁、已信任
- [ ] 手表与 iPhone 已配对
- [ ] 阶段 1 的 `developer_mode: True` 仍然成立
- [ ] 阶段 2 的 iLoader 已登录过**同一个** Apple ID

## 3.4 运行

两种方式**任选其一**，效果完全相同。

### 方式 A：图形界面（推荐）

```powershell
.\bin\HermesFixGui.exe
```

按界面顺序走：选 IPA → 填 Apple ID 与密码 → 点「开始签名并安装」。

中间会弹出验证码输入框，此时去 iPhone 上点「允许」抄 6 位数字填进去（默认是**推送**，不是短信）。
右上角四个进度块会依次变绿，日志面板里的内容与下一节的判据一一对应。

- 需要 **.NET 9 桌面运行时**；不想装就按 `scripts\build-gui.cmd` 末尾那条命令构建自包含版（约 57 MB）
- 点「停止」会连引擎子进程一起结束，不会留下卡住的进程

### 方式 B：命令行

```powershell
.\run-hermesfix.cmd
```

> 直接右键跑 `.ps1` 会报「禁止运行脚本」，这是 Windows 默认执行策略。
> `.cmd` 入口已经用 `-ExecutionPolicy Bypass` 只在当前进程绕过，不改系统设置。

按提示依次输入：

1. **Apple ID**（必须是阶段 2 用的那个）
2. **密码**（掩码输入，只经环境变量传递，不落盘、不进日志）
3. **两步验证码**（等 iPhone 弹窗 → 点允许 → 抄 6 位数字）

## 3.5 看日志（关键判据）

四个阶段，每个都有明确的成功标志：

| 阶段 | 期望看到 |
| --- | --- |
| 登录 | `login ok` |
| 开发者会话 | `session ok` |
| 找到设备 | `[3/4] Locating the USB iPhone ...` 之后没有报 `no usable iPhone` |
| **签名** | `App signed!` |
| **安装** | `Installing: 97%` → `Installing Apple Watch app: 100%` → `InstallComplete` |

如果之前成功签过名，还会看到：

```
Using existing private key from storage
Found matching certificate
```

这说明**复用了同一张证书，没有浪费额度**。

失败时先看日志尾部：

```powershell
Get-Content .\hermesfix.log -Tail 30
```

> **阶段 3 完成标志**：日志出现 `App signed!` 和 `InstallComplete`。

# 阶段 4 · 验证权限真的进去了

**这一步不能跳。** 它把"设备能不能用"和"签名对不对"分开，出问题时能立刻定位。

## 4.1 离线校验签名产物

签名后的 IPA 会被留在临时目录（程序设了 `delete_app_after_install = false`，就是为了事后核对）。
校验脚本可以直接吃这个目录，**不用重新打包**：

```powershell
python .\scripts\verify_appgroup.py "$env:TEMP\HermesEnabler.ipa_extracted"
```

**判据**：四项全 OK

```
[watch profile]  ... com.apple.security.application-groups = ['group.com.example.HermesEnabler.<TEAMID>']  -> OK
[iphone profile] ... -> OK
[iphone binary]  ... -> OK
[watch binary]   ... -> OK

全部通过（4 项）—— App Groups 已生效
```

其中 **`[watch ...]` 两项是核心**。修复前这里是 `MISSING`。

## 4.2 设备侧确认

手表上打开 HermesEnabler：

| 看到什么 | 说明 |
| --- | --- |
| 不再弹 *An App Group ID may be missing* | ✅ 权限生效，进入阶段 5 |
| 仍然报同样的错 | 装的是旧包 → 回阶段 3 重跑 |
| 闪退 | 签名过期或安装不完整 → 回阶段 3 重跑 |

> **阶段 4 完成标志**：4/4 OK **且** 手表打开 App 不报 App Group 错误。

# 阶段 5 · 装表盘

顺序很重要，**不要跳步**：

1. **先备份** —— 在 HermesEnabler 里执行 **Backup MG**，**确认备份真的成功**再往下
2. **打开 Hermès 开关**
3. **Restart Carousel**（重启表盘轮播，让新表盘被加载）
4. 在手表上切换到爱马仕表盘，确认显示正常

> 第 1 步失败就**不要继续**。表盘写入失败时，没有备份就只能重装。

> **阶段 5 完成标志**：手表上能切换到爱马仕表盘并正常显示。

# 阶段 6 · 7 天后续签

免费 Apple ID 的 Provisioning Profile 只有 **7 天**有效期。到期后 App 会闪退/打不开——这是正常的签名过期，不是数据损坏。

## 6.1 续签

```powershell
cd C:\hermes\hermes-watch-windows
.\run-hermesfix.cmd
```

脚本会复用已存私钥和证书，**不会新建也不会吊销**。

## 6.2 三做三不做

| 做 | 不做 |
| --- | --- |
| 到期后重跑脚本 | ❌ 在 iLoader 里撤销证书 |
| 保持同一 Apple ID | ❌ 换账号（会消耗新的证书额度） |
| 保持 iPhone 解锁 + 信任 | ❌ 删除 App / 清除数据 / 重置配对 |

## 6.3 什么时候要重装而不是只续签

- Profile 过期太久，iOS 已把 App 判为不可用
- 换过 Apple ID
- 换过手机

这三种情况重跑一遍阶段 3 即可。

# 附录 A · 给 AI Agent 的指令模板

想让 agent 帮你跑，把下面这段整段发给它（**按阶段发，不要一次发全部**）：

```text
你是我的 Windows 自动化执行 Agent。目标：在 Windows 上把 HermesEnabler 装到我的
Apple Watch，并让手表端拿到 App Groups 权限。

约束（违反任何一条立即停止并问我）：
1. 不重置手表/iPhone 配对，不清除任何设备数据，不升级系统，不关闭安全防护。
2. 不吊销任何证书，不删除已安装的 App。
3. 不把我的 Apple ID 密码、两步验证码写进任何日志、文件，或发送给第三方。
4. 涉及我在设备上的手动操作（开启开发者模式、输入验证码）时，暂停并告诉我具体怎么做。
5. 不编造命令。不确定就先查仓库文档或让我确认。

现在只执行【阶段 X】，完成后停下来汇报：
- 你执行了哪些命令
- 每步的实际输出
- 判据是否达成（文档里每步都有「判据」）
- 有没有偏离文档的地方

参考文档：https://github.com/YEZH0/hermes-watch-windows/blob/main/docs/00-%E4%BB%8E%E9%9B%B6%E5%BC%80%E5%A7%8B.md
```

**按阶段分批**的原因：一次给 6 个阶段，agent 会在某个判据没达成时硬着头皮往下走，最后失败得莫名其妙。

## 附录 A2 · 让 agent 代跑的边界

| 能自动 | 不能自动 |
| --- | --- |
| clone 仓库、建 venv、装依赖 | 手表上开开发者模式（要人点） |
| 跑 `--pair` / `--reveal-developer-mode` | 两步验证码（只推送到你手机） |
| 跑 `hermesfix`（可用 `HERMES_EMAIL` / `HERMES_PW` / `HERMES_UDID` 环境变量免交互） | Apple ID 密码（不建议交给 agent） |
| 跑 `verify_appgroup.py` 并解读结果 | 决定"要不要撤销证书"这种不可逆操作 |

# 附录 B · 错误速查

## 阶段 0/1

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Apple Mobile Device Service` 不存在 | 没装 iTunes / Apple Devices | 装驱动，重启 |
| `--pair` 超时（120s） | 手表不在充电器 / 不同 Wi-Fi / 锁屏 | 摆好设备重试 |
| 找不到「开发者模式」开关 | `--reveal-developer-mode` 没成功 | 重跑 1.5，确认手表解锁亮屏 |
| `developer_mode` 一直是 False | 开了开关但没重启 | 手表重启后再验证 |

## 阶段 2

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `-80045` | anisette 数据与 client-info 来源不一致 | 统一用同一个 anisette 服务，别混用工具 |
| `-45061` | 同账号在其他工具留了不一致的 provisioning | 复用 iLoader 的 keyring，不要新建 |
| 一直收不到验证码 | Apple 默认发推送不发短信 | 等 iPhone 弹窗，或输入 `sms` 切换 |
| 装完蓝牙/设备消失 | usbmux 会话回收 | 拔插数据线，不用重新配对 |

## 阶段 3

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 「禁止运行脚本」 | Windows 执行策略 | 用 `run-hermesfix.cmd` 而不是 `.ps1` |
| 提示证书数量超限 | 3 张额度用完 | 需要人工清理，先停下来问我 |
| 卡在 97% | 数据线/信任问题 | 拔插重试，不要中断进程 |
| `no usable iPhone` | 设备没连上 | 回阶段 0.4 检查 usbmux |

## 阶段 4/5

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `[watch *]` 显示 MISSING | 补丁没编进去 | 检查 `sideloader.rs` 是否还有 `continue` |
| 4/4 OK 但手表仍报错 | 装的是旧包 | 重跑阶段 3 |
| Backup MG 失败 | 共享容器不可写 | 说明 App Group 还没真正生效，回阶段 4 |
| 表盘不出现 | 没 Restart Carousel | 重跑第 3 步 |
